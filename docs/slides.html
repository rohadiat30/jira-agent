Bagian 01

Latar Belakang
& Masalah

Masalah

Deja Vu Tiap Subtask 🔁

Kalau ngoding manual, tiap mulai subtask developer mengulang langkah yang sama:

  1. Buka Jira, cari subtask yang mau dikerjakan
  2. Baca story description & acceptance criteria
  3. Pahami konteks & struktur repo dari awal
  4. Menyusun konteks jadi prompt untuk AI assistant
  5. Copy-paste manual bolak-balik Jira ↔ editor
  6. Ulangi dari langkah 1 untuk subtask berikutnya…
Akibatnya: berulang, makan waktu, rawan konteks terlewat, dan tidak konsisten antar developer.
Bagian 02

Ide Solusi

Solusi

Auto-Bridge Jira → Kiro

Saat subtask dipindah ke "In Progress", konteks Jira otomatis tersedia sebagai task file terstruktur di dalam repo — siap dikerjakan Kiro.
🖱️

Step 1

Pindah status subtask — aksi yang memang sudah biasa dilakukan.

🤖

Step 2

Buka task file, minta Kiro mengerjakannya. Tanpa copy-paste.

Prinsip

Empat prinsip

⚡

Trigger tanpa langkah baru

Pindah status yang sudah rutin, bukan aksi tambahan.

🧩

Konteks terstruktur

Title + description + AC + metadata dalam satu file.

🛡️

Developer pegang kendali

Tanpa commit otomatis.

📄

Dapat diinspeksi

Kontraknya cuma sebuah file .md.

Bagian 03

Cara Kerja

Alur end-to-end

Dari pindah status ke kode

1 Pindah subtask ke "In Progress"
2 Watcher (polling tiap 30s) mendeteksi transisi
3 Ambil konteks story: description, acceptance criteria, metadata
4 Tulis .kiro/tasks/<KEY>.md di repo target
5 Kiro membaca file → implementasi kode (tanpa commit)
6 Developer review & commit sendiri
Output

Isi task file

# Task: [FE] Added filter suspend on table history ift

## Jira Reference
| Subtask | NQLA-70940 — [FE] Added filter suspend... |
| Story   | NQLA-68834 — Sebagai Qlola, saya ingin... |
| Sprint  | 15 - Gladiator Sprint 29  |  Story Points | 3 |

## Subtask Title (fokus pekerjaan)
[FE] Added filter suspend on table history ift

## Story Description      ## Acceptance Criteria
...                       ...

## Instructions for Kiro
1. Pahami konteks repo...    5. JANGAN commit/push.
Satu file = satu prompt lengkap & konsisten.

Keputusan Desain

Keputusan

Empat keputusan kunci

Tanpa commit otomatis

Developer pengambil keputusan akhir.

📄

Task file sebagai kontrak

Sederhana, human-readable, versionable.

🔁

Anti-duplikat + regenerate

Ditulis sekali; hapus file = trigger ulang.

1️⃣

1 watcher = 1 repo

Sesuai pola "1 feature = 1 repo".

Pelajaran

Kiro Hook tidak cocok di sini

Pendekatan awal memakai hook PostFileCreate.

Ternyata tidak jalan — dokumentasi resmi Kiro: file hook hanya ter-trigger untuk file yang dibuat agent Kiro sendiri, bukan proses eksternal.
Solusi: balik arahnya — watcher yang memanggil Kiro (CLI headless). Verifikasi asumsi ke dokumentasi resmi menghemat waktu.
Bagian 07

Trade-off & Roadmap

Keterbatasan

Jujur soal batasan

  • Delay polling: deteksi maksimal setelah 1 interval (default 30s)
  • Batas 100 subtask per query → persempit JQL bila perlu
  • Ekstraksi AC best-effort → tergantung penamaan field di Jira
  • Mode otomatis butuh Kiro CLI + auth — mode semi-otomatis tetap andal
  • 1 instance = 1 repo → banyak repo butuh banyak instance
Roadmap
